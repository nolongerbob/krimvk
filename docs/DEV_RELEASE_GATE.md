# Проверка dev перед выпуском

Эта запись не подтверждает готовность рабочей базы и внешних сервисов. Production в ходе проверки не изменялся.

Актуальная процедура подготовки и результаты проверки сервера: [SAFE_RELEASE.md](./SAFE_RELEASE.md). Старый автоматический деплой заменён ручной подготовкой изолированного релиза без переключения трафика.

## Обязательные условия перед переключением

- Сверить релиз с текущей серверной версией. Защита показаний из `be4e74b` перенесена в dev; нельзя выпускать версию без неё.
- Установить `METER_SUBMISSION_DIR` в абсолютный постоянный каталог вне директории релиза, общий для всех процессов. Сохранить существующие reservation-файлы аварийного исправления. Не создавать пустой каталог вместо прежнего журнала. Без настройки новый production-код запрещает отправку показаний (503).
- Проверить права записи, резервную копию журнала и сохранность при откате. Несколько серверов с раздельными дисками эта защита не поддерживает.
- Проверить `prisma migrate status` на целевом окружении, план и резервную копию базы. Миграции SiteNotice, индексов и `20260928120000_utility_account_recovery` нельзя считать применёнными по результату локальной сборки. Последняя добавляет `messages.isSensitive` и журнал восстановления ЛС; она должна быть применена до запуска нового кода чата.
- Не использовать `db push --accept-data-loss` для выпуска. Изучить миграции и применять утверждённый план через `prisma migrate deploy`.
- Убедиться, что в окружение не попали настройки локального стенда, тестовый администратор и локальная база.
- Провести проверку авторизации, переписки двух пользователей/операторов, смены email с реальным письмом и загрузки закрытых документов в staging.
- Проверять отказ повторной отправки показаний на тестовой 1С; не отправлять искусственные показания в рабочие счета.

## Управление новыми функциями

Новая главная и ЛК включены одинаково в dev/production по умолчанию. `NEXT_PUBLIC_ACCOUNT_HOME_ENABLED=false` — явный откат вёрстки при сборке. Для карты адресов нужен `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` с ограничением на production-домен и необходимые API; CSP разрешает Google Maps только с заданным ключом и включённой новой главной. Карта аварий не включается. Социальные dev-предпросмотры автоматически в production не переносятся.

Остальные возможности включаются явными NEXT_PUBLIC_* флагами сборки. Капелька и осенние эффекты дополнительно требуют общих настроек администратора; при отсутствии или ошибке файла настроек обе функции выключены. Настройки хранятся вне релиза через SITE_RUNTIME_SETTINGS_FILE. ИИ требует серверный ключ, ASSISTANT_OPERATOR_ENABLED и постоянный ASSISTANT_BUDGET_DIR: максимум 200 попыток в сутки на VPS, 20 в минуту и 40 на пользователя в сутки. Бюджет не обнуляется при рестарте. Уведомления требуют миграции и активной записи с подходящими датами.

Новые операции паролей 1С запускаются отдельно: см. [UTILITY_ACCOUNT_ACCESS.md](./UTILITY_ACCOUNT_ACCESS.md). Не включать их на старом публичном HTTP-адресе.

## Что проверять сборкой

Запускать Jest, TypeScript и production build в отдельном каталоге без production `.env`. Успешная сборка с недоступной тестовой БД проверяет компиляцию, но не содержимое страниц из БД и не доступность 1С/почты/S3.

Все команды сборки (`build`, `build:vps`, `vercel-build`) только собирают приложение, не изменяя схему БД. ESLint проверяется сборкой. Подготовка VPS дополнительно проверяет runtime-зависимости через `npm audit` и останавливается при незакоммиченных/новых файлах: фиксировать только рассмотренные файлы релиза, не использовать слепое `git add .` для большой рабочей папки. Миграции и переключение трафика остаются отдельными операциями после резервного копирования.

## Локальная проверка кандидата 28.09.2026

Проверена копия рабочей папки, а не опубликованный commit. Production-сервер, его база, реальные пароли и показания 1С не изменялись.

- Чистая установка по `package-lock.json` через `npm ci --ignore-scripts`, затем явные Prisma generate и синхронизация BVI. Production build и отдельный TypeScript проходят. ESLint: 0 ошибок, 33 предупреждения (hooks, изображения, BVI); предупреждения не отключены.
- Jest: 665 тестов проходят. Ещё 3 opt-in сценария отдельно прошли на локальной PostgreSQL с подставной 1С: смена пароля с повторной проверкой результата, восстановление через подтверждённый email ЛК, привязка оператором счёта со счётчиками. Тестовые записи удалены. Это не проверка доступности рабочей 1С и не отправка реального письма.
- `npm audit --omit=dev`: 0 известных уязвимостей. MapLibre обновлён до 6.4.1. Проверка геометрии капли получила управляемые часы: нагрузка сборки больше не вызывает случайный провал 6-мс лимита; сам лимит отдельно проверяется и в приложении сохранён.
- 25 HTTP-проверок loopback production-кандидата прошли: публичные страницы, документы с фильтрацией, здоровье локальной БД, запрет анонимного доступа к ЛК/API/закрытым файлам. Dev-страницы возвращают Next not-found; ЕСИА-предпросмотр выключен.
- В браузере проверены новая главная и ЛК в production-режиме, отсутствие горизонтального переполнения на ширинах 320, 390, 639, 640, 1024, 1280 и 1440 px. Google Maps без ключа и реальные данные внешней 1С этим стендом не проверялись.
- Новая SQL-миграция проверена в отдельной временной схеме внутри транзакции: старое сообщение сохраняется с `isSensitive=false`, новые таблицы/индексы доступны. Транзакция откатана, схема отсутствует. Это не применение миграции на production и не замена репетиции на резервной копии целевой базы.

Перед выпуском остаются обязательные условия выше: резервная копия/миграции на целевом сервере, постоянный журнал показаний, ключ карты с ограничениями, проверка почты и закрытого хранилища. Новые методы паролей/почты 1С в production выключены до настройки HTTPS, ограничения доступа на стороне 1С и явного `ONE_C_UTILITY_ACCESS_ENABLED=true`; обычное чтение баланса и показаний этим флагом не отключается.
