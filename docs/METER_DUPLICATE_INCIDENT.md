# Повторы показаний — 21.09.2026

Прод до исправления: 5783a28. История 1С проверена read-only для двух счетов из обращения: `History` — объект с UNIX timestamp-ключами и массивами строк внутри. Сервер обходил объект через `for..of`, ловил исключение и продолжал запись. В журнале обнаружены 1209 сообщений `Could not check meter history`, 1202 `not iterable`; это суммарные счётчики файла, не число сегодняшних дублей. Последний релиз изменил парсинг чисел, но не этот алгоритм проверки.

Исправление:
- Поддержка объекта истории и массивов; неизвестный формат/ошибка блокируют запись.
- Общая защита в submitMeterReading для пользовательской и административной ручек.
- Одна эксклюзивная файловая резервация на район + счёт + счётчик + месяц (Europe/Moscow), до вызова 1С. `open(wx)` + fsync; повтор блокируется независимо от значения и пользователя.
- Резервация сохраняется после успеха, таймаута, перезапуска и удаления записи в 1С. Неопределённый результат нельзя автоматически повторять. Паролей в журнале нет.
- Директория `METER_SUBMISSION_DIR` должна быть постоянной и общей для всех процессов/релизов этого VPS. В production требуется явный абсолютный путь; fallback `.meter-submissions` в cwd разрешён только вне production. Не переносить на tmpfs, не очищать при деплое. Несколько серверов требуют общей транзакционной БД вместо этого single-VPS механизма.
- Нет автоматического повторения mutating GET или следования его redirect; отключён fetch-кэш.
- Форма не подставляет прошлые значения для отправки, не допускает параллельного submit, ждёт все ответы и исключает принятые счётчики из повтора после частичной ошибки.

## Ручная сверка

Техработы оставлять до проверки. Существующие дубли не удаляются кодом. Специалист 1С должен сверить непроведённые документы и подтвердить правильные значения. Файловый журнал покрывает отправки после установки защиты, не исторические запросы. История 1С блокирует уже видимые записи; удалённые до установки записи восстановить по ней нельзя.

Если результат `unknown`/`pending`: сначала проверить 1С, включая непроведённые документы. Только при доказанном отсутствии записи допустим контролируемый повтор с оператором; файл бездумно не удалять. При невозможности записать журнал передача запрещена.

Схема рабочей базы не меняется. Возврат на старую сборку не безопасен для приёма показаний: техработы должны оставаться включёнными до исправления или отдельной блокировки ручек.
