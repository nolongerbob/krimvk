# Шифрование паролей 1С в БД

Поле `userAccount.password1c` хранится в AES-256-GCM с префиксом `enc1:`.

## Настройка на VPS

```bash
cd /var/www/krimvk
bash scripts/generate-password1c-key.sh
# Добавить в .env:
# PASSWORD1C_ENCRYPTION_KEY=<вывод openssl>
```

После деплоя с ключом — миграция существующих plain-text записей:

```bash
set -a && source .env && set +a
npx tsx scripts/migrate-encrypt-password1c.ts
pm2 restart krimvk
```

## Поведение

| Ситуация | Результат |
|----------|-----------|
| Plain text в БД, ключ задан | читается как раньше; новые записи — `enc1:` |
| `enc1:` в БД, ключ верный | расшифровка для запросов в 1С |
| `enc1:` в БД, ключа нет | ошибка при вызове API 1С |
| Prod без ключа | добавление ЛС падает (нельзя сохранить пароль) |

Ключ: base64 на 32 байта, hex 64 символа, или произвольная фраза (берётся SHA-256).

**Не меняйте ключ** после миграции без перешифровки — старые `enc1:` станут нечитаемы.

## Проверка

1. Добавить ЛС в ЛК — успех, в БД значение начинается с `enc1:`  
2. Квитанция / показания / дашборд — данные из 1С как раньше
