# Важные уведомления (DEV)

Управление: `/admin/news` → «Важные уведомления» → `/admin/news/notices`.
Данные сохраняются в `site_notices`, связанной с `news`. Это обычная схема приложения, не localStorage-макет. Полоса на главной и в ЛК получает данные из `/api/news/notices`. Кнопка ведёт на `/news/{id}`.

- Поля: текст до 200 символов, подпись кнопки до 40, новость, начало и окончание, включение.
- Обе даты обязательны, вводятся в московском времени (UTC+3), хранятся в UTC.
- Показ: включено, начало <= серверное время < окончание, связанная новость опубликована.
- При пересечении периодов выбирается более позднее начало, затем id для стабильного порядка.
- Удаление новости каскадно удаляет её уведомления; перевод в черновик исключает из выдачи.
- При переходе и возвращении фокуса данные обновляются. На открытой странице опрос раз в 30 секунд; начало/редактирование/отключение отражаются в пределах этого интервала при доступной сети. На окончание дополнительно установлен таймер, рассчитанный относительно серверного времени. При ошибке API полоса скрывается.
- Крестик сворачивает конкретную версию уведомления до перезагрузки, остаётся кнопка повторного открытия. Изменённая версия показывается снова.

API управления проверяет роль администратора в БД через существующий requireAdmin. Публичная выдача не содержит черновиков, авторов и служебных данных.

## Перед production

Ничего не развёрнуто на production. Страница, обе API-ручки, пункт меню и подключение полосы пока ограничены NODE_ENV=development. Перед включением на production нужно согласованно заменить эти ограничения серверной настройкой, применить миграцию `20260921110000_site_notices` обычным процессом развёртывания, утвердить реальные тексты/новости и проверить на staging. Тестовые записи и `.local-dev` не переносить. Миграция добавляет только новую таблицу, индекс и внешний ключ; рабочие данные новостей не переписывает.
